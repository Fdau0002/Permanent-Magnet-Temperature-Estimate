# Separate written report: student completion guide

The brief requires an individual report with a 5–10-page body; references and appendices do not count toward that limit. The expanded notebooks and API documentation are not a claim that this separate report has been completed. Use fresh executed evidence rather than historical or test-fixture numbers.

| Suggested body allocation | Required content / source |
|---|---|
| 1 page | Engineering problem, intended use, scope, four fixed research questions |
| 1 page | Original source/provenance/units, profile split, causal 108-feature construction |
| 1–2 pages | Original optimisation, grouped objective, six model families and QR/kernel methods |
| 1 page | Independent numerical verification and actual test evidence, distinguished from predictive validation |
| 2 pages | Newly executed development comparison, exact/approximate SVR scalability, convergence and C sensitivity |
| 1 page | Newly executed final pooled/profile metrics and computational costs; fixed retrospective test limitation |
| 1 page | Engineering interpretation, limitations, learning and personal AI-use reflection |

Select a few readable figures rather than copying every notebook plot. Captions should name the source table, run ID, metric/units and inference limits. Do not change parameters in response to held-out performance. Clearly distinguish a known mathematical identity, development CV selection, final held-out validation and implementation testing. Explain any failed original-setting run honestly instead of implying successful full reproduction.
