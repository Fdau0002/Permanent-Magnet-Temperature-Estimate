# Data contract, provenance and units

**Source:** public *Electric Motor Temperature*, uploaded by Kirgsn (Wilhelm
Kirchgässner), collected by LEA, Paderborn University. Kaggle dataset version 3,
file `measures_v2.csv`. Public listing states 2 Hz and CC BY-SA 4.0. Principal
experimental provenance: Kirchgässner, Wallscheid and Böcker (2021), Table I
and Section III. Current project CSV is larger than that paper's described
139-hour subset; do not assume identical data selections.

One observation is one 0.5-second sample within a motor test session. The CSV
contains no explicit timestamp. Preserve the exact row order; elapsed seconds
are row position/2 within each profile. Session identifiers do not supply
absolute dates or chronological order between sessions.

| CSV field | Meaning | Units | Used as predictor? |
|---|---|---|---|
| `ambient` | Ambient temperature | °C | Yes, `theta_a` |
| `coolant` | Liquid coolant temperature | °C | Yes, `theta_c` |
| `u_d`, `u_q` | Actual voltage in rotating dq axes | V | Yes |
| `i_d`, `i_q` | Actual current in rotating dq axes | A | Yes |
| `motor_speed` | Mechanical rotation rate | rpm | Yes, `n_mech` |
| `pm` | Measured permanent-magnet surface temperature | °C | Prediction target only |
| `stator_winding` | Stator winding temperature | °C | No |
| `stator_tooth` | Stator tooth temperature | °C | No |
| `stator_yoke` | Stator yoke temperature | °C | No |
| `torque` | Motor shaft torque | N m | No |
| `profile_id` | Test-session grouping key | Dimensionless integer | Grouping only |

Motor speed conversion: omega = (2*pi/60)*n_mech, in rad/s.

| Derived predictor | Exact retained expression | Units/interpretation |
|---|---|---|
| `u_s` | hypot(u_d,u_q) | V |
| `i_s` | hypot(i_d,i_q) | A |
| `S_el` | 1.5*u_s*i_s | VA, apparent-power proxy under the benchmark dq convention; not measured real losses |
| `i_s_omega` | i_s*omega | A rad/s; current-speed interaction |
| `S_el_omega` | S_el*omega | VA rad/s; power-speed interaction |

For each of these twelve base inputs, four EWMAs and four population EWMSs
retain the same units as the base quantity. Feature names encode span in
samples. `config.py` specifies exact input order; per-model spans come only from the newly generated development manifest. The
experimental input domain is the observed operating envelope of this one
motor, not every physically possible value. Negative dq components/torque
are supported source observations, not automatically invalid. The workflow
does not clip or impose undocumented physical bounds. Observed ranges can
be regenerated with `raw.describe()`; they are not safety limits.

Exact source bytes: 300,061,411 bytes; SHA-256
`78f3d150f0f2ad9c5dc7ff24dd12c00d386ad530f48c1589ad24fcd88867d3ad`.
The table has 1,330,816 rows, 13 ordered columns and 69 contiguous profiles.
Structural validation rejects nonnumeric, nonfinite, missing, duplicate,
interleaved or incorrectly indexed input. No imputation, row deletion,
resampling or automatic unit inference is permitted. Sensor calibration,
noise and physical plausibility cannot be verified from these checks.

Primary output is estimated magnet temperature in °C at each source row.
Other outputs are row-aligned NPZ predictions, model-specific feature/schema
metadata, JSON settings/environment, joblib models, per-profile and pooled
CSV metrics, and PNG diagnostic figures. The README explains which outputs
are evidence and which files are regenerated intermediates.

The 2 Hz rate is documented by the source, not independently reconstructed from timestamps. Hidden dropped measurements or acquisition jitter cannot be diagnosed from a CSV with no timestamp field; elapsed-time plots assume the documented constant interval.

Actual observed minima/maxima for every raw field are supplied in [data_observed_ranges.csv](reports/data_observed_ranges.csv), regenerated by `scripts/fetch_data.py`. They describe this source file, not physically admissible limits, extrapolation guarantees or sensor-calibration acceptance criteria.
